# Обратная связь по PuuNote Sandbox

Привет! Как ИИ-ассистент, который вместе с пользователем создавал плагины (в частности, Voice Fixer) внутри этого окружения, я провел полный аудит архитектуры «Песочницы» и подготовил фидбек.

## Что сделано отлично (Плюсы)

1. **Изоляция и скорость:** Идея вынести разработку плагинов в отдельный минималистичный инвайронмент — 10 из 10. Отсутствие тяжелого стейта главного приложения (темы, дзен-моды, сложный роутинг) позволяет Vite мгновенно перезагружать код. Разрабатывать здесь в разы комфортнее, чем ковыряться в монолите.
2. **Четкий контракт (Plugin API):** Интерфейсы `PluginDefinition` и `PluginAPI` в `registry.ts` задают понятные рамки. Архитектура с хуками `init`, `unload`, абстракциями `cardActions` и `settingsComponent` — это очень правильно с точки зрения расширяемости.
3. **Мокирование карточек:** Наличие `document.getNode` и `updateNodeContent` сразу дает возможность писать плагины для работы с текстом и проверить их без сложных манипуляций.
4. **UI-контекст:** CSS-переменные (цвета, шрифты) сымитированы в `index.css`, поэтому верстка компонентов в песочнице выглядит почти так же, как в главном редакторе.

## Что нужно доработать (Чего не хватает)

В процессе переноса сложного плагина (Voice Fixer, требующий фоновой работы, работы с API и UI) мы столкнулись с рядом ограничений Песочницы:

### 1. UI Feedback (Уведомления и Фоновые задачи)
* **Проблема:** Плагинам часто нужно показывать пользователю, что что-то происходит (особенно при запросах к ИИ).
* **Решение в песочнице:** Нам пришлось "грязным" образом дописывать в `registry.ts` поддержку тостов (`api.toast`), джобов (`api.addJob`, `updateJobProgress`, `completeJob`) и рендерить их в `App.tsx`.
* **Рекомендация:** Добавить стандартизированные методы показа уведомлений и прогресс-баров в `PluginAPI`, чтобы они 1-в-1 совпадали с теми, что есть в основном приложении.

### 2. Управление глобальными настройками (Settings)
* **Проблема:** Сейчас плагину для получения глобального API-ключа от Gemini или списка моделей нужно лезть напрямую в `localStorage` (например, читать `GLOBAL_GEMINI_API_KEY`). Это нарушает инкапсуляцию, плюс названия ключей могут поменяться в основном приложении.
* **Рекомендация:** Добавить в `PluginAPI` метод для безопасного чтения/записи общих настроек. Например: `api.settings.getGlobal('geminiApiKey')`.

### 3. Расширение API работы с нодами (Карточками)
* **Проблема:** Доступны только методы чтения и обновления контента существующей карточки.
* **Рекомендация:** Добавить:
  * `api.document.addNode(content, afterId?)` — для создания новых карточек (например, если плагин хочет разбить длинную расшифровку на несколько частей по абзацам).
  * `api.document.deleteNode(id)`
  * События (Event Emitter) об изменении фокуса, чтобы плагин знал, какая карточка сейчас активна.

### 4. Оверлеи и Модалки (Custom UI Mounting)
* **Проблема:** Для показа индикатора записи в Voice Fixer нам пришлось вручную создавать DOM-элемент через `document.createElement('div')` и монтировать туда React-компонент через `createRoot`.
* **Рекомендация:** Было бы здорово иметь в `PluginAPI` метод вроде `api.ui.showModal(Component)` или `api.ui.showOverlay(Component, position)`, который бы безопасно рендерил UI плагина поверх интерфейса PuuNote.

### 5. Доступ к `aiModels` из ядра
* Функции работы с Gemini (фаллбэки, перебор ключей) у нас дублируются в `src/utils/aiModels.ts`. Скорее всего, в самом PuuNote этот механизм уже есть.
* **Рекомендация:** Вместо того чтобы каждый плагин тащил свою логику запросов к LLM (что раздувает бандл), лучше бы `PluginAPI` предоставлял прокси-метод. Например: `api.llm.generateText(prompt, options)`. А песочница могла бы этот метод просто мокировать или реализовывать локально, не заставляя авторов плагинов писать `fetch` к гуглу напрямую.

---
**Итог:** Инструмент отличный и выполняет свою задачу на 100%. Для идеала нужно лишь расширить `PluginAPI`, добавив методы по работе с UI (модалки, тосты, прогресс-бары) и созданием/удалением карточек, чтобы полностью симулировать возможности основного приложения.
